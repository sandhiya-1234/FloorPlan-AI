# Invalid artifacts (archived, do not cite)

These files were produced by earlier versions of the project. They are kept, not deleted, so the
project history stays honest (`git log` shows when they were created). **None of them is a result of
a fine-tuned Qwen2.5-VL model and none may be quoted as evidence of model quality.**
Background: `../technical_audit_2026-10-31.md`, `../model_training_audit_2026-10-31.md`,
`../data_integrity_report_2026-10-31.md`.

| Folder | What it is | Why it is invalid |
| :--- | :--- | :--- |
| `opencv_baseline_on_synthetic_fixtures/` | `metrics.json`, `classification_report.csv`, `comparison.png`, `error_analysis.png` | Scores of a hand-written OpenCV heuristic (not a trained model) on 3 procedurally generated fixture plans whose labels do not line up with the images. The old README presented them as the "Calibrated Pipeline" result; the error-analysis chart also used hard-coded placeholder IoU values. |
| `toy_surrogate_training/` | `training_history.json`, `training_loss.png`, `adapter_config.json` | Produced by `FloorPlanSurrogateModel`, a 2-layer toy transformer with a 2,000-token hash vocabulary trained for about 2 s on CPU. It is not Qwen2.5-VL and not a LoRA adapter, although the config file mimicked PEFT field names. The losses (7.88 to 7.04) say nothing about Qwen. The surrogate code has been deleted from `training/train.py`. |
| `ground_truth_copies_as_samples/` | `sample{1,2,3}.json` and `.png` | The old `predict.py` replaced its own output with the ground-truth sidecar JSON when one existed, so these "predictions" are copies of the labels. |
| `synthetic_fixture_dataset/` | the former `dataset/{processed,train,validation,test}` contents (15 plans) | Generated by `preprocessing/download_dataset.py`, not CubiCasa5K. All plans share one 4-room template, the images are not distinct floor plans, and the annotations do not correspond to the drawn images. Splitting 15 near-duplicates into train/val/test also leaks by construction. |

Rules for this folder: nothing here is read by any script, test, dashboard page or presentation slide.
If a number from here is ever needed, re-derive it from a verified run instead.
